What this proves

  • One PixiJS renderer can carry eight radically different visual families; the scene switch is a destroy-and-rebuild, not a new page.
  • Procedural drawing removes the raster-asset pipeline for these scenes: no image licensing, no atlas downloads, no 420 separate asset folders.
  • The expensive part is not the renderer. It is deciding what the entry should look like, checking the historical vocabulary, and reviewing the result.
  • Mobile, reduced motion and off-screen pausing are runtime concerns that can be solved once, in the player.

What it does not solve

  • Eight scenes are not 344. The visual families need a shared grammar so the dictionary does not become a gallery of unrelated posters.
  • Some entries need images, maps or portraits that cannot be drawn as pure geometry; those will add an asset pipeline.
  • Historical and symbolic review is still manual. A wrong zodiac order or a misread masonic symbol is a content error, not a rendering bug.
  • The pilot is a feasibility pass, not a production schedule. The next step is a costed family system, not 336 more one-offs.
